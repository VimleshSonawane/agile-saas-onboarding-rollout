# Retrospective

## What I created that worked

- A single progress view made the onboarding stages and owners visible, which was the core problem in the analysis.
- Early Security involvement avoided a late launch blocker in the plan.
- Sprint reviews forced a decision point after each sprint, instead of letting scope drift.

## What I analysed as needing improvement

- Import error wording needed plain-language fixes, identified in Sprint 2 feedback.
- Customer vs. internal actions were not clear enough in the first version of the checklist; this was redesigned in Sprint 3.
- Reporting for time in stage needs more work before a real production rollout.

## What I would change next

1. Add automated reminders for overdue stages, with owner escalation.
2. Add a second import format, after analysing which format pilot users actually requested most.
3. Add a short pilot interview script, so feedback is comparable across pilot customers.

## Significance for a PM role

This retrospective shows the part hiring managers often probe in interviews: not just what was built, but what was learned, what was changed because of evidence, and what would be done differently next time.
