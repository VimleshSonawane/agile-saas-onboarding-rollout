# RAID Log

RAID = Risks, Assumptions, Issues, Dependencies. Mitigations were planned early, not added after delays.

## Risks analysed

1. **Integration work runs late**
   - Mitigation created: start with the most common import format first; phase other formats to a future backlog.

2. **Scope grows mid-sprint from Sales/Partnerships requests**
   - Mitigation created: change log, weekly scope decision with the sponsor, and a clear out-of-scope list in the charter.

3. **Security/compliance review delays launch**
   - Mitigation created: involve Security/Legal in Sprint 1, complete review before pilot go-live.

4. **Pilot customers do not complete training**
   - Mitigation created: training linked to each stage, plus a completion checklist before handoff.

## Assumptions

- Simulated pilot customers represent three partner types: small, mid-size, and program partner.
- The demo is a static front-end example; production authentication and live integrations are out of scope for this project.
- Pilot metrics are simulation targets for the project, not real company results.

## Issues (simulated, for learning)

- Two usability issues in Sprint 2: unclear step ownership and import error wording. Both were logged, analysed, and addressed in Sprint 3.
- One scope request in Sprint 2 for an additional import format was deferred to the future backlog, with the reason recorded.

## Dependencies

- Security review depends on Sprint 1 stakeholder involvement.
- Training handoff depends on completion of the guided checklist.
- Go-live readiness depends on pilot feedback analysis and the retrospective.
